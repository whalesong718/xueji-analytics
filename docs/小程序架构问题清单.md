## 一、部署方式（核心决策）

### 当前引擎的问题
引擎是 Python 写的（FastAPI + 纯 Python 引擎），需要服务器运行。

**微信小程序不能直接跑 Python 代码，所以引擎必须部署在服务端。**

### 可选方案

| 方案 | 成本 | 复杂度 | 适用阶段 |
|------|------|--------|---------|
| A. 微信云开发（云函数） | 免费额度够用 | 低 | 上线 |
| B. 本机 WSL 跑 API 调试 | 0 | 低 | 开发 |
| C. 白嫖部署（Railway/Render等） | 免费 | 中 | 上线备选 |
| D. 买轻量云服务器 | 30-50元/月 | 中 | 稳定运营 |

**云函数说明：** 微信云开发支持 Node.js 和 Python 运行环境，你的 engine/ 目录可以直接部署为云函数。小程序调用云函数不需要配置域名、不需要服务器。

## 二、数据存储

### 数据库选型

| 方案 | 优点 | 缺点 |
|------|------|------|
| 微信云数据库（JSON文档型） | 和云函数无缝集成，免费额度够 | 查询能力有限 |
| SQLite（服务端文件） | 最简单，零配置 | 并发差，不适合多人 |
| MySQL/PostgreSQL | 成熟稳定 | 需要服务器 |

**云数据库适合小程序场景：** 每次作业一条记录，每周报告一条记录，不需要复杂联表查询。

### 数据结构

**需要存什么：**
- 用户/学生信息（绑定微信 openid）
- 作业记录（每次作业的 25 题详情）
- 分析报告（每周生成的报告 JSON）
- 错误类型配置（5 类错误的中英文映射）

**估计数据量：**
- 一个学生：每周 5 次作业 × 4 周 = 20 条记录
- 一年 ≈ 240 条 + 52 份报告
- 云数据库免费额度：同时存 100 个学生没问题

## 三、录入方式（用户体验关键）

这是小程序最影响体验的地方。每次 25 题，每题选对错+选错误类型，家长操作频率高。

### 可选方案

#### 方案 1：手动逐题勾选（简单但慢）
```
每道题显示：
  [正确]  [错误]  [空题]
  如果是错误 → 选类型：粗心/概念/计算/方法/审题
```
- 优点：数据准确，实现简单
- 缺点：25 题点完要 2-3 分钟

#### 方案 2：只填总数 + 标注错题（折中）
```
填写：
  - 总题数：25
  - 正确数：20
  - 错误数：5
  - 空题数：0
然后只对 5 道错题选错误类型
```
- 优点：快很多，30 秒完成
- 缺点：没有每道题详细记录

#### 方案 3：拍照识别（最理想，但需要 OCR）
```
拍作业本照片 → OCR 识别对错标记 → 自动填
```
- 优点：最快，拍一张照片就行
- 缺点：OCR 识别准确率不稳定，需要调试

## 四、API 接口设计

### 需要哪些接口

| 接口 | 用途 | 优先级 |
|------|------|--------|
| `POST /homework` | 录入一次作业 | P0 |
| `GET /homework/list` | 查看作业历史 | P0 |
| `POST /analyze` | 请求分析（跑全链路） | P0 |
| `GET /report/latest` | 获取最新报告 | P0 |
| `GET /report/history` | 历史报告列表 | P1 |
| `GET /report/{id}` | 某份报告详情 | P1 |
| `DELETE /homework/{id}` | 删除某次作业 | P2 |

### 协议格式
- 全部 JSON
- 鉴权：小程序 openid（微信云开发自动带）
- 错误码统一
